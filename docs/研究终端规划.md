# 研究终端规划与实施路线

> 产品主旨：多方法选股 → 观察队列 → 回测验证 → 复盘追踪（**不下单**）。  
> 本文是项目的产品设计、能力边界、实施路线和统一数据契约。

## 1. 项目定位

盘后 / 低频的 A 股研究推荐终端：

- 综合技术、资金、消息、博主观点，输出**可解释、可回测、可追踪的候选股票**。
- 辅助用户决策，但不自动下单，不追求实时盘口级交易，不承诺收益。

核心目标：

1. 发现候选股票
2. 给出明确风格：趋势 / 打板 / 低吸 / 龙头 / 事件 / 资金 / 观点
3. 给出推荐逻辑和证据
4. 给出关键价位和失效条件
5. 通过回测验证策略有效性
6. 通过观察队列和实际表现持续追踪

## 2. 核心用户流程

```text
打开项目
  ↓
今日推荐首页
  ↓
按风格查看候选：趋势 / 打板 / 低吸 / 龙头 / 事件 / 资金 / 观点
  ↓
点击股票，进入候选分析
  ↓
查看：为什么入选 + 证据 + 风格 + 关键价位 + 失效条件
  ↓
跳转 K 线确认
  ↓
加入观察队列
  ↓
后续复盘 / 回测 / 研究档案
```

## 6. 功能打通关系

```text
全市场行情 + K线
        ↓
技术 / 事件 / 观点 / 资金 / 龙虎 多通道信号
        ↓
统一候选模型 RecommendationRecord
        ↓
风格识别 + 融合评分 + 风险过滤
        ↓
今日推荐首页
        ↓
候选分析 / 工作台
        ↓
观察队列
        ↓
实际表现追踪 + 历史回测
        ↓
策略权重调整
```

关键打通点：

1. 数据管理 → 推荐系统：资金/龙虎/事件刷新后推荐系统自动读取。
2. 全市场 → 选股通道：行业、涨跌幅、换手、量比、市值、PE/PB 作为统一基础过滤。
3. 观察队列 → 回测：观察队列标的成为后续表现追踪样本。
4. 回测 → 推荐排序：回测表现好的策略权重更高，反之降权。
5. 推荐 → K 线：候选分析页一键跳转完整行情。
6. 研究档案 → 复盘：人工结论与历史推荐记录关联。

## 7. 统一数据模型

### 7.1 推荐记录

```ts
interface RecommendationRecord {
  id: string
  code: string
  name: string

  // 风格
  style: 'trend' | 'limit_up' | 'pullback' | 'leader' | 'event' | 'fund' | 'opinion'

  // 来源

    technical?: string[]
    event?: string[]
    opinion?: string[]
    fund?: string[]

  createdAt: number
}
```

## 8. 回测体系

回测是推荐系统的验证器，不是附属功能。

### 8.1 按风格定义回测规则

| 风格 | 回测思路 |
|------|----------|
| 趋势 | 均线/突破后持有 N 日，移动止损 |
| 低吸 | 超跌/回踩后买入，观察反弹 |
| 龙头 | 行业相对强度 + 换手 + 涨幅，持有 N 日 |
| 打板 | 涨停次日表现；必须考虑涨停不可买入 |
| 事件 | 事件发生后 N 日窗口收益 |
| 资金 | 主力连续净流入后 N 日表现 |
| 观点 | 博主共识后 N 日表现，样本稀疏时降权 |

### 8.2 统一评价指标

- 胜率
- 平均收益
- 中位收益
- 盈亏比
- 最大回撤
- 相对沪深300 / 中证500 / 同行业超额收益
- 目标命中率
- 止损触发率
- 交易次数是否足够

### 8.3 防过拟合

- 样本内 / 样本外分开
- 走步式回测
- 参数搜索范围限制
- 交易次数过少时标记“不可信”

### 8.4 成交可行性与偏差

- 涨跌停无法成交
- 一字板无法买入
- 停牌 / 流动性不足
- 避免未来函数
- 避免幸存者偏差

## 9. 分阶段实施计划

### P0：统一“推荐”这件事（当前优先）

1. 定义统一 RecommendationRecord。
2. 各通道输出统一结构。
3. 增加风格标签规则。
4. 开发「今日推荐」首页。
5. 推荐结果落库。

### P1：建立回测闭环（与 P0 同等重要）

1. 搭建统一回测引擎。
2. 支持技术、资金、龙虎、事件通道回测。
3. 增加风格回测：趋势 / 低吸 / 龙头 / 打板。
4. 统一回测指标。
5. 增加回测看板。

### P2：数据补强与推荐质量

1. 资金流备用源。
2. 龙虎榜多日缓存。
3. 基本面 B1：估值条件 + 轻量估值通道。
4. 消息面去重和行业映射优化。
5. 推荐冷却 / 去重 / 同板块集中度控制。

### P3：追踪与自动优化

1. 推荐表现追踪。
2. 策略自动降权 / 升权。
3. 每日推荐摘要通知。
4. 市场环境过滤：大盘趋势、情绪、涨跌停家数。
5. 更深的基本面数据。

## 10. 风险、边界与补充

- 通道产出的是候选，不是买卖信号。
- 密钥只放服务端 .env，不进仓库、不回显前端。
- 优先可解释、可缓存、可调度的规则聚合；LLM 仅用于解析/抽取。
- 打板回测必须考虑成交可行性。
- 同一板块、同一逻辑的股票避免过度集中推荐。
- 大盘明显弱势时，趋势和打板策略应自动降权。
- 记录数据来源、更新时间、失败原因、是否使用缓存。
- 支持人工复盘：用户是否采纳、结果如何。
