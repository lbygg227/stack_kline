# 研究终端规划与实施路线

> 产品主旨：多方法选股 → 观察队列 → 回测验证 → 复盘追踪（**不下单**）。  
> 本文是项目的产品设计、能力边界、实施路线和统一数据契约。

## 1. 项目定位

盘后 / 低频的 A 股研究推荐终端：

- 综合技术、资金、消息、博主观点，输出**可解释、可回测、可追踪的候选股票**。
- 辅助用户决策，但不自动下单，不追求实时盘口级交易，不承诺收益。

核心目标：

1. 发现候选股票
2. 给出明确风格：趋势 / 打板 / 低吸 / 龙头 / 事件 / 资金 / 观点
3. 给出推荐逻辑和证据
4. 给出关键价位和失效条件
5. 通过回测验证策略有效性
6. 通过观察队列和实际表现持续追踪

## 2. 核心用户流程

```text
打开项目
  ↓
今日推荐首页
  ↓
按风格查看候选：趋势 / 打板 / 低吸 / 龙头 / 事件 / 资金 / 观点
  ↓
点击股票，进入候选分析
  ↓
查看：为什么入选 + 证据 + 风格 + 关键价位 + 失效条件
  ↓
跳转 K 线确认
  ↓
加入观察队列
  ↓
后续复盘 / 回测 / 研究档案
```

## 6. 功能打通关系

```text
全市场行情 + K线
        ↓
技术 / 事件 / 观点 / 资金 / 龙虎 多通道信号
        ↓
统一候选模型 RecommendationRecord
        ↓
风格识别 + 融合评分 + 风险过滤
        ↓
今日推荐首页
        ↓
候选分析 / 工作台
        ↓
观察队列
        ↓
实际表现追踪 + 历史回测
        ↓
策略权重调整
```

关键打通点：

1. 数据管理 → 推荐系统：资金/龙虎/事件刷新后推荐系统自动读取。
2. 全市场 → 选股通道：行业、涨跌幅、换手、量比、市值、PE/PB 作为统一基础过滤。
3. 观察队列 → 回测：观察队列标的成为后续表现追踪样本。
4. 回测 → 推荐排序：回测表现好的策略权重更高，反之降权。
5. 推荐 → K 线：候选分析页一键跳转完整行情。
6. 研究档案 → 复盘：人工结论与历史推荐记录关联。

## 7. 统一数据模型

### 7.1 推荐记录

```ts
interface RecommendationRecord {
  id: string
  code: string
  name: string

  // 风格
  style: 'trend' | 'limit_up' | 'pullback' | 'leader' | 'event' | 'fund' | 'opinion'

  // 来源
  channels: Array<'technical' | 'event' | 'opinion' | 'fund' | 'dragon'>

  // 结论
  thesis: string
  confidence: number
  score: number

  // 通道原始证据（简短字符串，用于快速展示）
  evidence: {
    technical?: string[]
    event?: string[]
    opinion?: string[]
    fund?: string[]
    dragon?: string[]
  }

  // 结构化推荐理由：每条都带具体数值 + 事后验证口径
  reasons: RecommendationReason[]
  reasonSummary: {
    total: number
    byDimension: Record<string, number>
    topLabels: string[]
    reasonScore: number // 理由加权强度 0~100
  }

  // 推荐当时的基本面画像
  fundamentals?: FundamentalProfile

  // 生成这条推荐时实际使用的权重（可追溯、可对账）
  appliedWeights: {
    style: number
    dimension: number
    targetFactor: number
    confidenceScale: number
  }

  // 价位与失效
  levels: { entry?: number; target?: number; stopLoss?: number }
  invalidIf: string[]
  horizonDays: number

  // 时间与基准
  signalDate: string
  createdAt: number
  benchmark: string // 默认 sh000001，用于计算超额收益
}

interface RecommendationReason {
  dimension: 'fundamental' | 'technical' | 'fund' | 'dragon' | 'event' | 'opinion' | 'industry'
  key: string
  label: string   // 例：估值 低估 / 业绩高增长 / 主力连续净流入 / 博主看多
  detail: string  // 例：PE(TTM) 11.4，行业中位 24.4，行业估值分位 23%
  weight: number  // 该理由在结论中的权重
  strength: number // 理由强度 0~100
  metrics: Record<string, number | string> // 机器可读数值
  expect: string  // 事后验证口径，归因时按同一口径判定成立/证伪
  sources?: ReasonSourceLink[]
}

interface FundamentalProfile {
  peTtm?: number; peStatic?: number; pb?: number
  roe?: number
  revenueYi?: number; revenueYoy?: number
  netProfitYi?: number; profitYoy?: number
  grossMargin?: number; netMargin?: number; debtRatio?: number
  mainNetInflowYi?: number; mainNetInflowPct?: number
  mktcapYi?: number
  industryPeMedian?: number; industryPePercentile?: number
  valuationLabel?: string; growthLabel?: string; qualityLabel?: string
  rating: 'strong' | 'neutral' | 'weak'
  bullets: string[]
}
```

> 基本面来源：东财 clist 追加字段（f37 ROE / f41 营收同比 / f46 净利同比 / f49 毛利率 / f57 负债率 / f62 主力净流入 / f115 PE(TTM) / f100 行业 / f103 概念），
> 由 `refreshSlowVars` 合并进行情快照；东财不可达时主机自动降级（push2delay → push2 → 82.push2），字段缺失时理由只输出可得部分，不编造数值。

### 7.4 荐股归因闭环（理由 → 对账 → 改策略）

这是「推荐质量」的主链路，缺了它，推荐就只是每天一屏列表：

```
通道 / 基本面 / 资金 / 观点  ─┐
                            ├─→ RecommendationReason（带具体数值 + 验证口径）
                            │
推荐记录落库（含理由、权重快照）│
                            ↓
持有期结束 → RecommendationOutcome ─→ 逐条对账（涨跌 / 超额 / 目标 / 止损 / 见顶日）
                            ↓
              RecommendationAttribution（按维度、按理由、按共振数、校准、偏差）
                            ↓
        RecommendationWeights v2（风格权重 / 维度权重 / 目标价系数 / 置信度缩放 + 调整日志）
                            ↓
                     回写到下一次推荐（appliedWeights 可追溯）
```

关键口径：

| 概念 | 定义 |
|------|------|
| 对账结果 | 信号日次日开盘买入，持有 `horizonDays` 个交易日后收盘卖出（与模拟盘一致） |
| 基准 | 上证指数（`sh000001`），按实际买卖日对齐，停牌不影响 |
| 维度成立 | 该条推荐的该维度理由出现时，实际收益是否跑赢基准（excessPct > 0） |
| 校准误差 | 置信度区间内的预测胜率与实际胜率的加权偏差（ECE） |
| 目标高估 | 目标价隐含涨幅 − 实际平均收益 |
| 见顶日 | 持有期内最高点距买入的交易日数，用于判断持有期是否合理 |

输出（`GET /api/recommendations/attribution`）：

- `byDimension`：每个理由维度的样本数、上涨率、跑赢率、平均收益、平均超额、结论（有效 / 一般 / 无效 / 样本不足）
- `byLabel`：具体理由（估值低估、业绩高增长、主力连续净流入、博主看多…）的跑赢率
- `resonance`：按理由维度数分桶（1 / 2 / 3+），验证「多维共振是否更可靠」
- `bias`：目标价隐含 vs 实际、目标命中率、止损触发率、平均见顶日、置信度校准表
- `suggestions`：可直接执行的结论，例如「资金面理由 12 个样本跑赢大盘 33% → 权重下调至 0.72」

### 7.5 权重自校准（v2）

`data/recommendation-weights.json`（v2）：

```ts
{
  version: 2,
  weights: { trend: 1.08, limit_up: 0.9, ... },        // 风格权重
  dimensionWeights: { fund: 1.15, opinion: 0.72, ... }, // 理由维度权重
  targetFactor: 0.62,        // 目标价系数（按实际可达幅度缩放）
  confidenceScale: 0.86,     // 置信度整体缩放（按校准误差）
  adjustments: [{ at, scope, key, from, to, samples, reason }] // 每次调整的依据
}
```

- 仅当某维度样本 ≥ 5 时才调整，且新旧权重按 0.5 平滑，避免小样本过拟合。
- 置信度公式：`evidenceScore × 验证系数 × 风格权重 × 维度权重 × confidenceScale`，
  其中 `evidenceScore = 通道分 × 0.6 + 理由分 × 0.4`。
- 目标价 = 入场价 × (1 + 基础目标幅度 × targetFactor)，避免系统性高估。
- 每次生成推荐都会写入 `appliedWeights`，事后可回答「这条推荐当时是按什么标准选出来的」。

## 8. 回测体系

回测是推荐系统的验证器，不是附属功能。

### 8.1 按风格定义回测规则

| 风格 | 回测思路 |
|------|----------|
| 趋势 | 均线/突破后持有 N 日，移动止损 |
| 低吸 | 超跌/回踩后买入，观察反弹 |
| 龙头 | 行业相对强度 + 换手 + 涨幅，持有 N 日 |
| 打板 | 涨停次日表现；必须考虑涨停不可买入 |
| 事件 | 事件发生后 N 日窗口收益 |
| 资金 | 主力连续净流入后 N 日表现 |
| 观点 | 博主共识后 N 日表现，样本稀疏时降权 |

### 8.2 统一评价指标

- 胜率
- 平均收益
- 中位收益
- 盈亏比
- 最大回撤
- 相对沪深300 / 中证500 / 同行业超额收益
- 目标命中率
- 止损触发率
- 交易次数是否足够

### 8.3 防过拟合

- 样本内 / 样本外分开
- 走步式回测
- 参数搜索范围限制
- 交易次数过少时标记“不可信”

### 8.4 成交可行性与偏差

- 涨跌停无法成交
- 一字板无法买入
- 停牌 / 流动性不足
- 避免未来函数
- 避免幸存者偏差

## 10. 风险、边界与补充

- 通道产出的是候选，不是买卖信号。
- 密钥只放服务端 .env，不进仓库、不回显前端。
- 优先可解释、可缓存、可调度的规则聚合；LLM 仅用于解析/抽取。
- 打板回测必须考虑成交可行性。
- 同一板块、同一逻辑的股票避免过度集中推荐。
- 大盘明显弱势时，趋势和打板策略应自动降权。
- 记录数据来源、更新时间、失败原因、是否使用缓存。
- 支持人工复盘：用户是否采纳、结果如何。

### 14.6 RPS（相对价格强度）调研与本地实测（2026-09-17）

**定义**：RPS = Relative Price Strength，把个股近 N 个交易日的涨幅放到全市场排名换算成 0-100 百分位
（`RPS = (1 − 排名/总数) × 100`），常用窗口 RPS50 / RPS120 / RPS250；欧奈尔体系要求 RPS ≥ 87，
国内「月线反转」流派用「RPS 强 + 结构紧凑 + 月线反转」。它是**横截面相对值**，天然剔除大盘 beta。

**本地实测**（`data/kline-cache` 前复权日线，等权全市场为基准，调仓间隔 20 个交易日，超额 = 个股 − 当期横截面均值）：

```text
样本 A：宽横截面（2025-09-11 ~ 2026-08-12，12 次调仓，每次约 5000 只）
  RPS50  → 未来 20 日   平均 IC −0.115（IR −2.6）  最强十分位 −0.39%、最弱 +0.87% → 明显反转
  RPS120 → 未来 20 日   平均 IC −0.057（IR −1.2）
  RPS250 → 未来 20 日   平均 IC −0.065（IR −1.3）
  RPS50/120/250 → 未来 5 日   平均 IC ≈ 0（+0.008 / +0.006 / +0.001）→ 无信息

样本 B：长历史子集（2013-04 ~ 2026-08，87 次调仓，平均横截面仅 978 只，见下方数据质量提示）
  RPS250 → 未来 20 日   平均 IC −0.009，但最强十分位 −2.78% vs 最弱 +0.30% → 极端强势组跑输
  分年度 IC：2019-2020 为正（+0.02 ~ +0.05），2021-2025 多为负 → 依赖市场环境
```

**结论**：

1. **作为 A 股选股因子，RPS 在 1-6 个月尺度上不是广泛有效，方向甚至偏反转**：过去 2 个月最强的 10%
   在随后 1 个月跑输最弱 10% 约 1.3pct（RPS50，横截面 5000 只、12 次调仓）。这与「A 股短中期反转、
   动量弱」的既有认知一致；美股式的「领导股延续」在 A 股不能照搬。
2. 5 日尺度 IC ≈ 0，**不能当短线信号**用。
3. 与项目已有指标的关系：我们已有的「显著强于板块」（行业内相对强度）、板块轮动分与板块阶段、
   涨停辨识度都是**局部横截面**；RPS 补的是**全市场横截面**，但补上来的这一维在中长周期是反转的。
4. 值得保留的用途（不做打分因子）：
   - 作为**上下文标签**（如「RPS250 92 = 全市场前 8%」），给人看，不进置信度
   - 作为**追高警示**：RPS50 ≥ 98 且无资金/板块支撑 → 软提示（现有 guard 已有追高分支，可挂上去）
   - ⚠️ 与「板块高位阶段反而更强」（§15.8.1）并不矛盾但需分辨：**板块**维度是关注度/资金聚集（强者恒强），
     **个股**维度单纯涨幅高则容易均值回归。后续可测「板块内按 RPS 分层」，这是目前唯一没拆开的口径。

**⚠️ 数据质量提示（影响本项目所有历史回测）**：本地 `data/kline-cache` 在 2026-09-16/17 的日常预热中
被以 `requestedCount=500` 重新拉取，深历史被截断——现状是 4837 只只有 500 根（约 2024-09 起），

## 15. 涨停板与情绪周期模块（P4，已实现）

> 实现状态：`server/limit-up.ts` + `/api/limit-up` + 「涨停板」页面 + 推荐侧 `board` 通道（leader / limit_up / relay）。

### 15.1 为什么值得单独做

板块启动几乎总是由**某一支个股的涨停**打出辨识度：先有龙头封板，再有同板块跟随，最后出现分歧与退潮。
因此「涨停 → 连板 → 板块梯队 → 情绪相位」是推荐系统里最贴近 A 股真实交易结构的一条线，
也是现有实现最薄弱的环节（当前只用 `changePct >= 9.8` 近似判定涨停，创业板/科创板 20% 涨跌幅会被误判）。

|----|------|
| 涨跌幅限制 | 主板 10%、科创板 688 / 创业板 300·301 20%、北交所 30%、ST 主板 5%（ST 创业板/科创板仍 20%） |
| 涨停判定 | `price >= round(prevClose × (1 + 限制), 2)`，**不再用 9.8% 近似** |
| 跌停判定 | 同理向下取整 |
| 炸板 | `high` 触及涨停价但收盘未封住；并记录炸板次数（分时） |
| 连板高度 | 用日 K 逐日回溯：`close(d) == 涨停价(close(d-1))` 的最大连续天数 |
| 首次封板时间 | 用当日 1 分钟 K 线，第一根 `close == 涨停价` 的时间（越早越强） |
| 板块 | 申万一级行业 + 东财概念（快照 `concepts`）双维度聚合 |

### 15.3 输出的指标体系

```ts
interface LimitUpBoard {
  date: string
  limitUp: BoardItem[]      // 涨停池：板数 / 首次封板时间 / 成交额 / 换手 / 主力净流入 / 板块
  limitDown: BoardItem[]    // 跌停池
  broken: BoardItem[]       // 炸板池（含炸板次数）
  ladder: Record<number, number>  // 连板梯队：1板 N 家、2板 N 家……
  sectors: SectorBoard[]    // 板块梯队：涨停家数 / 最高板 / 龙头 / 平均涨幅
  sentiment: {
    limitUpCount, limitDownCount, brokenRate, maxBoard,
    promotionRate,          // 昨日首板→今日连板的晋级率
    yesterdayPremium,       // 昨日涨停股今日平均涨幅（打板赚钱效应）
    phase: '冰点' | '启动' | '发酵' | '高潮' | '退潮'
    score: number
  }
}
```

**辨识度评分**（每只涨停股）：连板高度 40 + 板块内涨停家数 20 + 成交额排名 20 + 首次封板时间 15 + 炸板扣分 5。
用户提到的「打出辨识度」在这里落地为：**同一板块内，辨识度最高 = 板块龙头**。

### 15.4 情绪相位 → 推荐权重（把温度计从二元升级为五相）

| 相位 | 判定（简化） | 推荐取向 |
|------|-------------|---------|
| 冰点 | 涨停 < 30 且最高板 ≤ 2 | 首板/低吸优先，禁高位接力 |
| 启动 | 涨停 30–60，炸板率 < 30% | 首板 + 板块内补涨（性价比最好） |
| 发酵 | 涨停 60–100，最高板 3–5 | 龙头接力 + 补涨 |
| 高潮 | 涨停 > 100 或最高板 ≥ 5 | 只做龙头，警惕分歧 |
| 退潮 | 炸板率 > 45% 或跌停 > 30 或昨日溢价为负 | 打板/龙头权重下调，低吸/趋势优先 |

### 15.5 落到推荐（本模块的唯一目的）

新增理由维度 `board` 与三个风格：

1. **`leader` 龙头**：板块内辨识度第一且连板 ≥ 2 → 接力逻辑，验证口径「次日不炸板、3 日内不破 5 日线」
2. **`limit_up` 打板**：板块内涨停家数 ≥ 3 的首板（低位、有板块效应）→ 验证口径「次日高开或继续封板」
3. **`relay` 补涨**：热点板块内尚未涨停、但量价与资金配合的二线 → 验证口径「3 日内跑赢板块」

配套约束：
- 退潮/冰点相位下高位板直接进入观察名单（复用 `recommendation-guard`）
- 炸板股、跌停股不进入推荐池
- 每条推荐都带板块上下文理由（「CCL 概念 5 家涨停、最高 3 板，本股首板 09:41 封板、成交额板块第 2」）

### 15.6 历史回测结论（2012-12 ~ 2026-09，1440 个交易日 / 5411 只）

```text
口径：信号日=涨停当天；打板=涨停日收盘买、次日收盘卖；接力=次日开盘买、次日收盘卖
可成交口径 = 剔除当日一字板（买不到）与次日一字板，共剔除 4373 个样本

全样本            58.2%     +1.94%     +2.08%     -0.35%
可成交口径         55.1%     +1.36%     +0.99%     -0.30%
  1板             55.2%     +1.40%     +1.14%     -0.25%
  2板             53.2%     +1.14%     +0.35%     -0.52%

```

**三条结论（已写进权重与守卫）**：

1. **打板赚的是隔夜溢价，不是盘中接力**：打板口径全线正期望，接力口径全线负期望，且板位越高越差。
2. **剔除一字板后「板位越高越好」消失**（全样本 5 板 +3.36% → 可成交 5 板 +1.00%）：高板位的超额主要来自买不到的一字板。
   因此高位板不再额外加权，5 连板以上直接进观察名单。
3. **退潮期打板收益最低**（+0.52%，3 日转负），冰点期反而最好（+1.32%）→ 相位权重据此调整。

### 15.7 板块效应与板块内选股

板块启动 → 龙头封板 → 同板块跟随 → 分歧退潮，这条链路的可量化部分：

| 层 | 指标 |
|----|------|
| 当日板块梯队 | 涨停家数、最高板、连板梯队、板块主力净流入、最早封板时间、炸板家数、**板块热度 0-100**、龙头（辨识度第一） |
| 板块趋势 | 近 66 个交易日涨停家数序列 → 近 3 日均 vs 前 3 日均、连续在榜天数、活跃度、**升温 / 持平 / 退潮**、**5 日动量**、**生命周期阶段** |
| 板块内选股 | **补涨池**：板块热度 25 + 落后龙头幅度 25 + 资金（净流入与连续天数）30 + 量价 20；排除已涨停、大跌、无量、主力明显流出 |

推荐侧：每条记录带板块上下文（热度/梯队/首封/板块资金/是否龙头），「板块效应」理由会写成
「半导体概念 今日 12 家涨停（2板 1 家、1板 11 家），最早 09:36 封板，板块主力净流入 21.69亿；本股为板块内辨识度第一」。

### 15.8.1 板块生命周期：刚启动 vs 已经涨了一周

只看「升温/退潮」无法区分**刚点火**和**已经涨了一周**——两者都显示「升温」，但风险收益完全不同。
因此引入两个新字段并进入回测分桶：

| 字段 | 口径 |
|------|------|
| `change5d` | 板块成员近 5 个交易日的平均涨幅按日**复利累计**（%） |
| `stage` | 生命周期阶段：刚启动 / 持续升温 / 高位 / 退潮 / 震荡 |

判定规则（`classifySectorStage`，纯函数、单测覆盖）：

```text
退潮      ：5 日累计 ≤ -4%，或（趋势退潮 且 5 日累计不为正）
高位      ：5 日累计 ≥ +8%，或（连续活跃 ≥ 4 日 且 5 日累计 ≥ +4%） → 钱已经进来一周
刚启动    ：连续活跃 ≤ 2 日、今日 ≥2 家涨停、5 日累计在 [-1%, +4%) → 刚点火、涨幅还没走出来
持续升温  ：趋势升温 且 5 日累计为正（中段）
震荡      ：其余（含「刚出现但动量仍为负」——点火证据不足）
```

宽基概念（一带一路、人工智能等）几乎每天都有成员涨停，`streak` 常年等于窗口长度，
因此 **streak 必须配合涨幅一起看**，否则会把所有宽概念都判成「高位」——这也是把 `change5d` 放进判定的原因。

回测侧新增 `byStage` 分桶（信号日前一交易日的阶段）。实测（2026-06-17 ~ 09-17，5566 个涨停样本）：

```text
板块高位      928 样本  胜率 59.6%  打板均收益 +2.04%  持有3日 +3.15%
板块持续升温  988 样本  胜率 54.7%  打板均收益 +1.40%  持有3日 +0.12%
板块刚启动     79 样本  胜率 53.2%  打板均收益 +1.10%  持有3日 +1.40%
板块退潮      886 样本  胜率 51.8%  打板均收益 +0.99%  持有3日 +0.45%
板块震荡     2329 样本  胜率 51.1%  打板均收益 +0.96%  持有3日 +0.49%
```

**结论与直觉相反**：在这段样本里「已经涨了一周」的高位板块反而更强（+2.04% vs 震荡 +0.96%，差 1.08pct，
n=928），刚启动样本仅 79 个且只有 +1.10%——**板块层面是强者恒强，不是「刚启动更安全」**。
但样本只有 66 个交易日、单一市场环境，因此按收缩原则只取一半力度落地：

- 板块阶段乘数：高位 ×1.04、持续升温 ×1.02、其余 ×1.00（退潮不再额外扣，已由趋势 ×0.92 覆盖）
- 与趋势乘数口径部分重叠（都基于涨停家数序列），**合并后设上限 ×1.12**，避免重复加成
- 阶段与 5 日动量进入推荐理由与板块上下文（抽屉里可见「板块阶段 / 板块趋势」）
- 跨区间复验（至少覆盖一次退潮市）后再决定是否加满力度 → 见 §14 待办

界面：板块趋势榜新增「5 日动量」列 + 阶段标签 + 阶段筛选（带各阶段板块数）。

### 15.8.2 进入每日复盘摘要

日报新增「板块热度与轮动」段，位置在「市场温度」之后、「今日推荐」之前——**先回答今天钱在往哪切，再给推荐**：

1. 情绪相位（评分、涨停/跌停家数、炸板率、最高板、昨日溢价、晋级率）
2. 最热板块 TOP3（热度、涨停家数、最高板、龙头）
3. 升温板块 TOP3（阶段、3 日均 vs 前 3 日均、5 日动量）
4. **刚启动（可跟）TOP3** / **已在高位（谨慎追）TOP3**
5. 退潮板块 TOP2
6. 资金切入（轮动榜 TOP3，含排名变化）与资金撤出

### 15.9 验证与防过拟合

- 复用统一归因：`board` 维度的跑赢率与平均超额独立统计，与其它维度可比
- 连板高度、首次封板时间等指标进入结构化理由，**回测时按同一口径判定成立/证伪**
- 情绪相位的历史序列落盘（`data/limit-up-history.json`），可用于「相位 vs 次日打板溢价」的统计验证
- 注意样本偏差：注册制 20% 涨跌幅、北交所 30% 与主板 10% 不可混算，回测需按涨跌幅限制分组

### 15.10 看板新鲜度治理（2026-09-17 修复「今日推荐数据延迟」）

**现象**：今日推荐里的涨停池、情绪相位、板块龙头、打板/龙头候选整体停留在上一个交易日
（实测 09-17 盘中页面仍显示 09-16 的 94 家涨停 / 相位「高潮」，而当日实际是 55 家 / 发酵）。

**根因**（三处叠加）：

1. `currentLimitUpBoard()`（推荐接口、日报、板块补涨池都走它）只读「内存缓存 → 落盘快照」，**自己不重算**；
   旧实现把落盘的**昨日快照**塞进内存并标记成 `at = now - 9min`，于是新鲜度时钟被每次调用重置，
   `/api/limit-up` 的 10 分钟过期判断永远不成立 → 当日看板永远算不出来。
2. **没有任何定时任务重算看板**：只有「进程重启后第一次请求」或手动 `?force=1` 才会算。
3. 分时（m1）缓存里可能是前一天的分钟线，`sealStats` 直接拿来算，会把昨天的封板时间/炸板次数记到今天。

**修复**：

| 层 | 改动 |
|----|------|
| 新鲜度 | 新增 `server/board-cache.ts`：`expectedBoardDate()`（周末回退到最近工作日）+ `resolveBoard()` 纯函数——**只有日期等于当日的快照才允许回填内存**，过期快照只作兜底并标记 `needsRefresh` |
| 定时 | 新增 `LimitUpBoardScheduler`：启动即算一次（服务重启后立刻恢复当日看板），盘中每 5 分钟重算，收盘后当日看板就绪即停 |
| 后台兜底 | 推荐/日报路径发现快照过期时，触发一次后台重算（同刻只跑一个，60 秒节流），不必等用户打开涨停板页 |
| 分时口径 | `buildLimitUpBoardFull` 用 `filterSessionBars(bars, signalDateOf(now))` 只取当日分钟线 |
| 可见性 | 推荐接口返回 `boardDate / boardStale / boardExpectedDate`；今日推荐顶部显示「板块数据 09-17」，落后时标红；标题下显示「数据 HH:MM:SS（每 2 分钟自动刷新）」并加静默轮询 |

**验证**：把落盘快照人为改成 2026-09-16 后重启 → 启动日志自动打出
`[limit-up] 2026-09-17 涨停 55 / 跌停 3 / 炸板 29 情绪 发酵(68)`，推荐接口 `boardStale=false`，
`board` 通道 21 条中 9 条来自当日涨停池（其余为板块补涨）；单测覆盖新鲜度判定、周末回退、盘中窗口、分时按日过滤（4 条）。

## 16. 我的观点工作台（P1 + P2，已实现）

> 入口：桌面一级导航「我的观点」，移动端底部导航「观点」。
> 实现：`server/thesis-desk.ts` + `/api/thesis/*` + `src/components/ThesisDesk.vue`。

### 16.1 为什么需要

原系统里的 AI 都是单向的：个股 AI 点评（`/api/analysis/ai`）只输出简报、不接受用户观点；
AI 选股（`/api/ai-strategy`）只做条件解析；观点研究只处理**博主**的观点。
用户自己的判断（"固态电池是主线，先导基电回调到 20 日线可以低吸"）既无处验证，也无法回测。

### 16.2 交互形态

左侧输入/对话，右侧**证据面板**——不是聊天机器人，而是「举证 + 反证」的对账台：

1. 写下观点 → LLM **只做结构化**：标的 / 方向 / 风格（趋势·打板·低吸·龙头·补涨·事件·基本面·观点）/ 持有期 / 1~4 条可检验逻辑
2. 服务端聚合数据包（**全部来自本地，不新增外部请求**）：技术面（`analyzeStock`）、资金（近 5 日主力净额与连续流入天数）、龙虎榜、涨停板与板块梯队、板块趋势/阶段/5 日动量/轮动排名、估值与财务硬伤、情绪相位、博主观点（逐字校验通过）
3. 事实翻译成 **support / against / neutral** 三类，带数字与数据来源
4. 逐条逻辑按**关键词**取证（"龙头"看板块地位、"回调"看位置事实、"资金"看主力净额），数据不足就老实标 `unknown`，不硬凑结论
5. 加权支持度（维度权重与推荐理由同口径，中性事实不参与打分）→ 结论（支持 / 分歧 / 偏向反面）+ 失效条件 + 关键观察点
6. 引用本地已验证的回测分桶给出「历史同类情形」（样本数 + 胜率 + 区间）
7. 多轮讨论：`POST /api/thesis/discuss`，每轮重新取证；问不出来时返回 `neededData`（缺哪些数据），而不是顺着用户说
8. 一键落成记录（落盘时**重新对账**，不沿用前端传回的事实），此后按「次日开盘买入、持有 N 个交易日收盘卖出」结算超额（基准沪深 300）

### 16.3 接口

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/api/thesis/analyze` | 结构化 + 数据对账 + 结论（不落盘） |
| POST | `/api/thesis` | 落成我的观点记录（服务端重新对账后落盘） |
| GET | `/api/thesis` | 记录列表 + 统计（会顺带结算到期记录） |
| DELETE | `/api/thesis/:id` | 删除记录 |
| POST | `/api/thesis/discuss` | 多轮讨论（返回 reply 与 neededData） |

落盘文件：`data/my-thesis.json`。

### 16.4 硬约束

**模型只做结构化与措辞，结论与数字一律来自本地数据与回测。** 规则引擎先算出支持度与结论，
模型只能在「事实清单」范围内措辞且必须同时给反证；历史同类情形引用已有回测分桶

### 16.5 实测样例（2026-09-17）

## 17. 趋势票「启动」研究（2026-09-18，含实测结论）

### 17.1 问题

用户观察：金牛化工（sh600722）、会稽山（sh601579）此前趋势走得很好，
**怎样才能提前找到下一个类似会走趋势的票？**

### 17.2 两只样本的启动前指纹（本地日线，前复权）

| 样本 | 启动日 | 启动前一日：距 60 日高 | 20 日振幅 | 近 5 日量能 | 均线极差(MA5/10/20) |
|------|--------|------------------------|-----------|-------------|---------------------|
| 金牛化工 | 2026-01-06（+7.45%，量比 4.8x） | −14.8% | 11.2% | 0.97x | **0.3%** |
| 会稽山 | 2025-04-01（+5.83%，量比 4.85x，次日 +10% 量比 7.9x） | −7.8% | 8.3% | 1.17x | 2.0% |

共同点：**长期横盘 → 波动率压缩 → 量能萎缩到地量 → 均线粘合 → 突然放量长阳**；
且启动后常伴随回踩（金牛 1/16 −9.76% 洗盘后继续，会稽山 4/1~4/7 平台整理后加速）。

### 17.3 实测：这个指纹没有预测力（全市场事件研究）

样本：本地日线 5360 只；信号日收盘买入；超额 = 个股收益 − 同日全市场等权收益。

```text
做法                                        样本    20日超额   胜率    20日内涨过30%   -8%止损触发
全部「放量大涨」(≥5% 且 量比≥2.5)          33997    -3.65%   32.5%      12.6%          52.7%
+ 低位(距60日高≤-10%) + 压缩(20日振幅<12%)  1517    -3.34%   32.8%       6.2%          37.8%
连续 3 日放量（每日量比≥2.5）                6501    -4.92%   30.7%      10.1%          54.5%
```

另外（形态分层，20 日超额）：平台突破放量 −0.32%、均线粘合发散 −0.01%、长横盘新高 +0.08%、
趋势回踩 20 日线 −0.78%、底部放量异动 −1.91%（最差）、首板放量 +0.04%（5 日 +0.90%）。

> ⚠️ **勘误（2026-09-18）**：本文档初版曾写「改在回踩 MA10 收阳时买入，从 −3.34% 改善到 +0.58%」，
> 那是**口径不一致的错误对比**——−3.34% 是相对同日全市场等权的超额，+0.58% 是不减基准的绝对收益
> （当时市场 20 日平均约 +1.6%）。**同口径下回踩入场并未改善**：压缩突破事件 1494 个，
> 触发日买入 20 日超额 −0.67%，改回踩 MA10 收阳买入 −1.24%（见 17.6）。

**结论**：

1. **"下一个金牛化工"事前选不出来**：把两只票的形态指纹量化后拿到全市场，1517 个同类样本的
   20 日超额是 −3.34%，只有 6.2% 的样本 20 日内涨过 30%。记住的是分子，分母是上千个长得一样的票。
2. **换入场时机救不回来**：触发日买入 −0.67%、回踩 MA10 收阳买入 −1.24%（同口径），
   入场择时的差异远小于「有没有 α」这件事本身。
3. **爆量不要追**：单日量比 >3 与连续 3 日放量都是负期望（与"连续放量=吸筹"的直觉相反，更像换手/出货）。
4. **必须按右尾设计仓位**：12.6% 的样本 20 日内涨过 30%，但 52.7% 会触发 −8% 止损 → 低胜率、正偏度。
   只买一两只赌它成妖，长期必然亏；只能小仓位 + 分散 + 严格止损 + 让盈利奔跑。

### 17.4 因此正确的产品形态：两段式「启动雷达」

| 段 | 条件 | 产出 |
|----|------|------|
| ① 待启动观察池（**不买**） | 距 60 日高 ≤ −10% + 20 日振幅 <12% + 近 5 日量能 <1.0x + 均线极差 <5% | 实测 2026-09-16 有 **407 只**——形态不稀缺，必须二级过滤 |
| ② 触发 + 确认（**候选**） | 观察池内出现放量长阳（≥5%、量比 2~3）→ 等**回踩 MA10/MA20 收阳** | 二级过滤：板块阶段（刚启动/持续升温）、情绪相位、主力资金连续净流入、三线共识分 → 压到 10~30 只 |
| ③ 失效条件 | 跌破 MA20、板块阶段转退潮、主力资金连续净流出 | 每条候选都带失效条件，进推荐理由与归因闭环 |

### 17.5 状态过滤检验（2026-09-18 完成）：结论是**不做**

压缩突破事件（低位 ≤−10% + 20 日振幅 <12% + 放量大涨 ≥5%/量比 ≥2.5）1494 个，
按市场状态与量能分档（20 日超额，基准为同日全市场等权）：

```text
全部：触发日买入                         n=1494   -0.67%   胜率 35.7%
全部：回踩 MA10 收阳买入                  n=1135   -1.24%   胜率 37.3%

按市场宽度（信号日全市场上涨占比）
  弱市 <40%：触发日买                     n= 422   -1.17%   31.0%
  中性 40~60%：触发日买                   n= 394   -0.98%   38.8%
  强势 >60%：触发日买                     n= 678   +0.11%   36.7%   ← 状态过滤确实有效（差 1.3pct），但仍不为正
  强势 >60%：回踩买                       n= 530   -1.58%   36.6%

按全市场涨停家数（情绪代理）
  <20 家（冰点）：回踩买                   n= 164   +0.34%   43.3%
  45~90 家（发酵）：触发日买                n= 634   -2.38%   31.1%   ← 最差
  ≥90 家（高潮）：触发日买                  n= 615   +0.44%   38.5%

最优子集（强势市 + 量比<3 + 回踩买）        n= 171   -0.20%   胜率 46.8%
```

**结论：状态过滤能把相对表现拉高约 1.3pct（强势市 +0.11% vs 弱市 −1.17%），但整套「压缩突破」
即使叠加状态过滤与入场择时，最优子集仍是 −0.20% 的负期望。因此不做「启动雷达」策略。**
形态本身不是 α 来源，状态过滤只能改善相对排序，救不回一个没有 α 的信号。

保留的部分：入场时机做成了通用能力（§17.7），观察池随时可以用「筛选器」形式提供，
但只作为人工看盘的范围收敛工具，不进推荐打分。

### 17.6 回测架构升级（2026-09-18）

原引擎只能验证「筛选器 + 固定持有期」，无法验证买入时机与止损 —— 这是所有形态策略无法被检验的根因。
本次给 `runPortfolioBacktest` 补齐三块：

| 能力 | 配置 | 说明 |
|------|------|------|
| 入场时机 | `entryMode: nextOpen \| pullbackConfirm \| breakoutConfirm` + `pullbackMa` / `pullbackTolerancePct` / `confirmMaxWaitDays` | 触发后等待回踩均线收阳或重新站上触发价再买；超时计入 `entryTimeout` |
| 止损与止盈 | `stopLossPct` / `trailingStartPct` / `trailingBackPct` | 收盘价触发，跌停无法卖出时顺延（沿用原逻辑） |
| 状态过滤 | `allowedPhases` / `minUpRatio` + 注入的 `regime: Map<date, {upRatio, limitUpCount, phase}>` | 信号日不满足状态直接拦掉，计入 `regimeRejected` |

同时修正一个口径 bug：**持有期过去从「信号日」起算，等于少持有一天；现在从「买入日」起算**。
指标与成交记录也补齐：`exits{time,stop,trailing,endOfData}`、`averageHoldingDays`、`averageWaitDays`、
每笔的 `waitDays` / `exitReason` / `maxFavorablePct` / `maxAdversePct`。

### 17.7 买入时机（荐股的最后一公里）

新增 `server/entry-plan.ts`：对每条推荐给出**可执行的入场计划**（不是预测，是条件）：

| 模式 | 触发条件 | 输出 |
|------|----------|------|
| 可买 now | 距 MA20 ≤3%、20 日振幅压缩、MA20 上行 | 次日开盘可买，回踩 MA10 加仓 |
| 等回踩 pullback | 距 MA20 >12%（追高） | 挂单价 = MA10 附近，等收阳 |
| 等确认 confirm | 距 MA20 3~12%，或打板/龙头风格 | 回踩 MA10 收阳，或收盘站上今日高点；打板类要求次日不破今日收盘价 |
| 先观察 wait | MA20 未走平向上 | 等 MA20 上行且站上 MA20 |

每条都带硬止损（策略止损与 MA20×0.98 取低）与依据说明。推荐接口返回 `entryPlans`，
今日推荐表格新增「买入时机」列、详情抽屉给出完整说明（实测 55 条推荐全部有计划）。

## 18. 分板推荐与「重点推荐」准入（2026-09-18）

### 18.1 问题

推荐一次给出 50+ 只，用户无法判断该看哪几个；且主板、创业板、科创板的涨跌幅规则与风险特征完全不同，
混在一张表里没有可比性。

### 18.2 做法：全量保留 + 每板最多 5 个「有回测证据」的重点

| 层 | 内容 |
|----|------|
| 分板 | 主板（sh60 / sz00，含原中小板）、创业板（sz30）、科创板（sh688）、北交所（bj），按代码前缀判定 |
| 全量列表 | 每个板块各自的全部推荐（表格 + 买入时机 + 个股回测列），不删减 |
| **重点推荐** | 每板最多 5 个，**必须通过个股历史回测准入**，宁缺毋滥（不足 5 个就少给，并在界面上说明被挡下的原因） |

### 18.3 个股回测口径（`server/signal-backtest.ts`）

只用本地日线、可复现、无未来数据：

| 信号口径 | 重放规则（按风格映射） |
|----------|------------------------|
| 打板 `limit_up` | 当日涨幅达到该板涨跌幅上限（主板 10% / 创业板·科创板 20% / 北交所 30%）；对应 style limit_up / leader / relay |
| 突破 `ma_breakout` | 收盘创 60 日新高且量比 ≥1.3；对应 style trend |
| 回踩 `pullback_ma10` | 现价在 MA10 ±3% 内、收阳、MA20 上行；对应 style pullback |
| 趋势跟随 `trend_follow` | MA20 上行且收盘站上 MA20 并收阳；对应 event / fund / opinion 等 |

- 入场：信号次日开盘；出场：持有 `horizonDays` 个交易日收盘
- **基准：该股自身同持有期平均收益**（同一段历史任意一天买入持有 N 日的均值）——
  这样自动扣除个股漂移与 beta，不需要外部指数，也不会把「这只票本来就在涨」误当成信号有效
- 同时给出 **−8% 硬止损触发率**（低胜率正偏度的信号必须看这个）

准入四条硬门槛：有日线 → 样本 ≥6 → 历史平均超额 >0 → 止损率 ≤45%，另外置信度 ≥20。
排序分 `focusScore = 置信度 × (1 + 样本加权后的历史超额)`。

### 18.5 设计取舍

- **不按"置信度前 5"取重点**：置信度是当期打分，无法回答"这套逻辑在这只票上历史上管不管用"；
  现在两者都要过，才进重点。
- **不删全量列表**：用户明确要求保留全部推荐，重点只是"先看这几只"的入口。
- **允许某个板块没有重点**：科创板只有 4 只候选且都没有足够历史信号，硬凑 5 个等于骗自己；
  界面直接把被挡下的原因写出来，比给一个假重点更有用。
- 局限：`horizonDays` 用的推荐持有期（3~10 日），单个信号口径也只覆盖技术面；
  资金/龙虎榜/观点这些通道的历史数据我们没有留档，因此这部分历史表现只能靠通道基线（§15/§17）推断。

## 19. 历史资金流 / 龙虎榜回补与「重点推荐」跟踪（2026-09-18）

### 19.1 历史数据能不能查到？能，但各有上限

| 数据 | 数据源 | 历史能力（实测） | 落盘 |
|------|--------|------------------|------|
| 资金流（日频主力/大单/超大单净额） | 东方财富 `fflow/kline/get`（push2his） | 单只一次最多 **120 个交易日**（约半年）；`fflow/daykline/get` 与 `lmt=0` 均返回空 | `data/fund-flow-history.json` |
| 龙虎榜（净买额/机构/游资） | 扶摇 `dragon-tiger-list?date=YYYY-MM-DD` | **支持任意历史交易日**，逐日回补 | `data/dragon-tiger-history.json` |
| 观点 | — | 按用户要求**不做** | — |

⚠️ **必须限速**：实测 4 并发连打 55 只 × 2 轮后，东财对来源 IP 直接断连（http=000），需等待一段时间才恢复。
因此回补默认**并发 1、间隔 800ms**，连续失败 5 次自动停止并提示"疑似被限流、稍后续传"，
已回补的股票默认跳过（断点续传），`force=true` 才重拉。

接口：`POST /api/history/backfill { kind: 'fund'|'dragon', codes?, days?, dragonDays?, limit?, force? }`，
`GET /api/history/backfill` 查进度与已覆盖数量。

### 19.2 资金线 / 龙虎榜线进入个股回测

`signal-backtest.ts` 新增两种可重放口径（需要历史数据，缺失时自动跳过）：

- `fund_inflow`：**主力连续两日净流入**（资金线）
- `dragon_buy`：**当日上榜且净买为正**（龙虎榜线）

推荐接口返回 `evidenceBacktests`，重点卡片上直接显示这两条线的历史样本与超额。
实测第一次回补（限流前）：龙虎榜覆盖 60 个交易日、0 失败；资金流因触发限流只拿到 1 天/只，

### 19.3 重点推荐自己也要被回测（`server/focus-tracking.ts`）

- 每日把 `boards[].focus` 落盘到 `data/focus-picks.json`（同一天同一只票只记一次）；
- 结算口径与推荐一致：**次日开盘买入 → 持有 `horizonDays` 个交易日收盘卖出**，基准沪深 300；
- 同时记录持有期内最大浮亏（`maxAdversePct`），因为重点推荐是"我们已经承诺有证据"的那一档；
- `GET /api/focus-picks` 返回明细与统计（按板块、按风格拆分，样本 <20 条时明确提示"仅作观察"）；
- 今日推荐页顶部新增「重点推荐跟踪」条，直接显示已结算数、胜率、平均超额。

为什么必要：准入规则（样本 ≥6、历史超额 >0、止损率 ≤45%）如果自己不被检验，就是自说自话。
